역할별 화면 구성과 사용 방법

가로형 페이지를 기준으로 왼쪽은 화면 구성(와이어프레임), 오른쪽은 사용설명입니다. 현재 시스템은 정적 홈페이지 + Express/MongoDB API로 동작하며, 로그인 역할은 상주(family) · 관리자(admin) · 슈퍼바이저(supervisor)입니다. 시각은 한국시간(KST, Asia/Seoul) 기준이며, 변경 이력은 감사 로그에 남습니다.

시스템 흐름

브라우저 → 정적 페이지 (index / pages) → Express API (/api) → MongoDB

공개 홈페이지는 누구나 열람합니다. 상주·관리자·슈퍼바이저는 /pages/member/login.html 통합 로그인 후 역할에 따라 상주 포털(/pages/member/*) 또는 관리 콘솔(/admin/)로 이동합니다. 슈퍼바이저도 동일 콘솔을 쓰며, 간편 모드(조회·승인·감사)로 메뉴가 축소됩니다.

역할과 로그인

현장 관리자(admin)와 감독(supervisor)을 나눕니다. 슈퍼바이저도 /admin/에 들어가지만 간편 모드 메뉴만 보입니다.

  1. 기본 계정: 아이디 basic / 비밀번호 basic4444 (환경변수 SUPERVISOR_*로 변경 가능).
  2. 조회: 빈소 이용, 회원 리스트(아이디·비밀번호), 주문, 문의, 감사 로그.
  3. 승인: 빈소 신청 승인/거절, 고액 주문(awaiting_supervisor) 확정, 사후정산.
  4. 제한: 품목·요금 등록/수정/삭제, 상주 계정 생성·삭제 UI·API는 관리자 전용.
고액 주문 상세에서 「슈퍼바이저 승인」을 누르면 상태가 확인(confirmed)으로 바뀌고 감사 로그에 기록됩니다.

현재 상태 · 운영 체크리스트

한 줄 평가

공개 안내 → 상주 예약 → 관리자 정산 → 슈퍼바이저 승인·감사까지 이어지는 3역할 실무 구조가 구현되어 있습니다. 운영 시 기본 계정 비밀번호 변경과 고액 기준(100만 원)만 현장 규정에 맞게 조정하면 됩니다.

반영된 기능

  • 슈퍼바이저 역할 · 간편 모드 메뉴
  • 변경 감사 로그(계정·요금·주문·로그인)
  • 상주 최초 비밀번호 변경·이용 안내 체크리스트
  • 고액 주문 슈퍼바이저 2차 승인
  • 회원 리스트(아이디·비밀번호)·KST·모바일 햄버거 메뉴
  • 홈페이지 비주얼 CMS(메인 홈 슬롯 편집)

운영 시 확인

  • ADMIN_* / SUPERVISOR_* 비밀번호 교체
  • HIGH_VALUE_ORDER_THRESHOLD 현장 기준 조정
  • 상주 계정 전달 후 최초 설정 완료 여부 확인
  • 발인 전 사후정산·문서 출력 점검

권장 운영 순서

  • 1) 관리자: 빈소 이용 등록 → 상주 계정 발급
  • 2) 상주: 로그인 → 최초 설정 → 장례 예약
  • 3) 관리자: 주문 확인·사후정산 → 문서 출력
  • 4) 슈퍼바이저: 고액 승인·감사 로그·빈소 신청 점검

역할 유지 원칙

  • 홈페이지 = 게스트 「안내」
  • 상주 포털 = 「거래·예약」
  • 관리자 = 「운영」 / 슈퍼바이저 = 「감독·승인」
